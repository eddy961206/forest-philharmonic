# 스피어: 화면 표면에서 먼 공간으로

## 요청과 범위

구형 공연장의 내부를 단순히 네모 스크린을 휘어 놓은 방이 아니라, 관객 주위와 머리 위로 하나의 세계가 이어지는 공간으로 만들기 위한 변경이야. 코드·장면 조사, 투영 설계, 구현, 회귀 검사와 재현 가능한 시각 진단을 포함해. 최초 조사 기준은 **30c223e98add1eda19c9cd410e9bfddc339cd81d**였고, 작업 중 PR #17과 #18이 병합되어 최종 제품 기준을 **5078d155075326a3859901d34093b9f8377f8be0**으로 올렸어. bfd6dc5 시점의 1차 증거와 최신 통합 증거는 구분해 기록해. PR #16·#17의 새 연출과 통로 조명을 보존해. 최근 숲·구름·고딕 성당·금빛 천장·비·눈의 아트 변경은 덮어쓰지 않아.

사용자가 이번 작업에는 Codex 작업을 새로 만들거나 자신의 PC를 사용하지 말고 dot의 클라우드 환경에서 작업하라고 명시했어. 해당 방식으로 실행했고, main 병합·자동 병합·Sites 배포는 범위에 포함하지 않았어.

## 조사: 실제 돔과 가상 공연장의 차이

- [Sphere Studios / Media Plane](https://www.thesphere.com/studios-proxy/spherestudios/canvases): 화면이 관객의 위와 주변을 감싸는 연속된 시야가 핵심이야. 이 자료는 몰입 연출의 방향을 지지하지만 이 코드의 성능이나 체감 개선을 증명하지는 않아.
- [Derivative / Projection TOP](https://derivative.ca/UserGuide/Projection_TOP): 큐브맵·위경도·피시아이 등 표현 사이의 투영 변환을 다루고 있어. 이 프로젝트에는 이미 방향 기반 셰이더와 큐브맵이 있으므로, 16:9 영상을 늘리거나 TouchDesigner를 런타임 의존성으로 추가할 필요가 없어.
- [Unity / 3D Skybox](https://github.com/Unity-Technologies/UniversalRenderingExamples/wiki/3D-Skybox): 먼 배경의 깊이감과 카메라 이동 시 시차는 다른 문제야. 1차 변경은 무한 원경의 방향 보정이었고, 2차에서는 일부 장면에 유한 깊이 시차를 추가했어. 근거리 나무 사이를 자유롭게 걷는 6DoF 세계는 아니야.

실제 LED 돔은 여러 관객이 **같은 물리 표면**을 봐. 특정 기준 시점에 맞춘 그림은 그 자리를 벗어나면 다른 모양으로 보이는 것이 물리적으로 정상이지. 반면 브라우저의 가상 공연장은 방문자별로 화면을 따로 렌더할 수 있어. 따라서 실제 공연장 재현과 가상 공간 몰입을 분리하고, 어느 쪽인지 명시적으로 선택하게 했어. 실제 Sphere의 제작 시스템을 그대로 구현했다거나 전문 장비로 현장 보정했다고 주장하지 않아.

## 기존 구조의 진단

`domeshow.js`는 모든 장면을 `normalize(surfacePoint - SP.VIEW)`로 평가했어. `SP.VIEW=(0,19,34)`에서 보면 일관되지만, 옆자리·상층 관객의 화면 광선과 달라. 그 결과 먼 달·별·지평선의 방향과 각 크기가 돔의 위치에 묶여 변해. 이것은 원래 공연장 투영 모델의 특성이며 셰이더 오류로 단정하지 않아.

문제는 그 물리 모델을 모든 자연 장면의 유일한 몰입 방식으로 사용했다는 점이야. 새로운 모드는 먼 세계의 광선을 `normalize(surfacePoint - cameraPosition)`으로 평가해. 달을 보기 위해 고개를 돌리는 각도와 달의 각 크기가 관객의 위치 때문에 임의로 바뀌지 않게 해.

## 구현 선택

### 두 모드

- **공간 몰입**: 앱의 새 기본값. 자연 장면은 현재 렌더 카메라의 방향을 사용해. 가까운 객석·난간은 실제 geometry로 움직이고, 천체와 대부분의 자연 배경은 무한 원경으로 남아. MOON/STARS/저사양 FOREST의 일부 레이어는 아래 2차 구현에 따라 유한 깊이 시차를 가져.
- **공연장 투영**: 이전 중앙 기준 투영을 선택 가능하게 보존해. 실제 공용 LED 표면의 외관을 비교하거나 원래 연출을 원하는 경우 사용해.

UI는 스피어 설정에만 노출하고 `aria-pressed`와 기존 설정 저장 경로를 사용해. 홀에서는 숨겨. 잘못된 저장 값은 정규화해. 네트워크 방 상태·호스트 권한·음원 시계를 바꾸지 않아. 개인별 시각 설정이므로 방 전체의 재생 상태로 동기화하지 않아.

### 화면에 붙어 있어야 하는 것

ARCH, CATHEDRAL, GOLD, DECO는 구조·천장 장식이므로 기존 기준점에 고정해. 라이브 무대 중계와 자막도 screenAz/screenEl로 제자리에 둬. 새 풍경 방향으로 중계 사각형까지 계산하면 화면이 관객을 따라다니는 부작용이 생기기 때문이야.

천장이 열리는 reveal 경계도 고정된 화면 방향을 사용해. 두 패스 각각 자신의 장면 ID로 광선을 선택하므로, 물리 천장과 원경 사이의 crossfade를 섞어서 정의하지 않아. 추가 shader program, render target, 전체 화면 postprocess, 고해상도 텍스처, raymarch step 증가는 없어.

### 보이지 않는 큐브 면의 정합성

원경 셰이더가 샘플링하는 방향을 바꾸면, 큐브맵 가시성 검사도 같은 원점을 사용해야 해. 그렇지 않으면 이전 sweet spot의 가시성 마스크가 새 방향에서 필요한 면을 생략해 검은 영역을 만들 수 있어.

카메라별 캐시에 투영 모드를 포함했고, 모드 변경 시 기존 큐브를 무효화해 필요한 면을 다시 그려. 시간·비행 경과는 초기화하지 않아. 특히 상층에서 아래쪽 화면을 보는 경우 -Y 면이 필요할 수 있어, 무조건 생략하던 처리를 제거했어. 기존 renderer의 기본 요청은 다섯 면(0x37)으로 유지하고, 몰입 모드에서 실제 마스크에 포함된 -Y만 렌더해. 따라서 어떤 시점에서는 면 하나의 추가 비용이 생길 수 있어. 비용 0이나 무조건 성능 향상을 주장하지 않아.

### 전문가식 진단 도구

`__fp.hall.dome.setCalibration(true)`는 실제 제품 셰이더 안에서 15도 간격 위경도 선, 수평선, 달과 동일 방향·각 크기의 원형 표적을 보여줘. `false`로 복원해. 이것은 UV 벽지 격자가 아니라 관측 광선 기준 격자야. 측면/상층에서 원형 표적의 왜곡과 수평선 연속성을 비교할 수 있어. 일반 UI에는 진단 버튼을 추가하지 않아.

## 보존한 범위와 제외한 작업

- 기존 음악, PCM, 공간 음향, 카메라 이동·좌석 선택, 무대 중계 내용, 최신 PR #16 아트는 그대로야.
- 기존 통로·계단·난간 geometry/재질/조명은 건드리지 않아. PR #17에 새로 들어온 통로 조명 변경도 보존했지만, 실제 휴대폰의 어두운 통로 문제까지 이 PR이 검증했다고 주장하지 않아.
- 이슈 #13/#14/#15의 곡 로딩 경합·끝 seek 동기화·오디오 resume는 PR #18에서 수정됐어. 최신 main의 해당 변경을 보존하며 이 PR의 성과로 세지 않아.
- 1차 몰입 모드의 원경은 **회전**에만 맞았어. 2차에서는 MOON/STARS/저사양 FOREST에 한정해 **이동 시 유한 깊이 시차**를 추가했어. 다른 장면 전체가 같은 시차를 제공하는 것은 아니야. 진짜 6DoF 공간을 만들려면 깊이/geometry/관객 위치에 따른 별도 렌더링이 필요하고 모바일 비용도 달라져.
- VR 양안·물리 프로젝터 edge blending·다중 관객 sweet-spot 최적화는 구현하지 않았어.

## 재현

1. 기준 커밋과 후보를 각각 확보해. Node 18 이상으로 `npm test`를 실행해.
2. `npm start`로 후보를 실행하고 `/?venue=sphere&lobby=`로 열어.
3. 설정의 **스피어 공간 표현**에서 두 모드를 비교해. 중계 위치, 좌석·난간의 위치가 바뀌지 않는지 확인해.
4. 개발자 콘솔에서 `__fp.hall.dome.go('MOON')`, `setCalibration(true)`로 중앙/측면/상층을 확인해. 진단 후 `setCalibration(false)`로 돌려.
5. 별도 Playwright 설치를 이용해 `CHROME_EXECUTABLE`, `PLAYWRIGHT_MODULE`, `BASE_URL`, `OUTPUT_DIR`를 지정하고 `node tools/bench/dome-projection.mjs`를 실행해.

브라우저 도구는 고정 640×360/DPR1, low, 관객0, 애니메이션 정지, 시스템 폰트 조건으로 같은 후보의 두 모드를 비교해. 고정 광선 차이를 격리하기 위한 fixture이며 전체 공연 FPS나 실폰 성능 시험이 아니야. 각각의 완료시간은 직접 render + gl.finish 동기 대기 시간이고 앱 FPS로 변환하면 안 돼. 이미지 내용 자체가 달라지므로 같은 화질 성능 비교로도 부르면 안 돼.

## 검증 결과

최종 실행 결과와 원본 로그/캡처 목록은 같은 폴더의 증거 파일 및 PR 본문에 기록해. 통과·실패·미실행을 분리해서 읽어야 해. 실제 휴대폰, 사람의 음악 청취, 장시간 발열, 물리 GPU 성능은 이 클라우드 작업에서 확인하지 못해.

## 사용자 피드백 뒤의 연출 보강

처음 투영 비교를 본 사용자는 정지 사진에서 큰 차이를 느끼기 어렵다고 피드백했어. 그 판단은 타당해. 방향 보정만으로 공간 전체가 다른 세계로 바뀌는 체감까지 입증할 수 없기 때문이야. 그래서 투영 보정만을 최종 성공으로 삼지 않고, MOON/STARS의 공간적 구성을 보강했어.

- 객석 너머의 낮은 시야에 세 겹 능선과 달빛 계곡 안개를 더했어. 먼 능선은 밝고 옅은 청색, 가까운 능선은 어둡고 선명하게 분리해 대기 원근감을 줘.
- 위쪽 밤하늘을 가리거나 UI 위에 반투명 필터를 덮는 방식이 아니야. 모두 돔 재질 내부의 원경에만 적용해. 계단/객석/무대 조명은 그대로야.
- 능선의 방위각 주파수는 정수이므로 ±π 이음새에서 주기적으로 닫혀. 카메라를 돌릴 때 원경이 끊어지거나 옆으로 스크롤하지 않도록 했어.
- 매 프레임 움직이는 카메라/번쩍이는 조명은 추가하지 않아. 음악을 방해하지 않는 고정된 원경이야.
- 달의 이전 흰 원판에 가장자리 명암과 넓은 표면 무늬를 더하고 출력을 낮춰, 번진 흰 점보다는 형태가 있는 먼 천체로 보이게 했어. 천문학적으로 정확한 달 표면/위상 재현은 아니야.
- MOON과 최상위 STARS 경로에만 적용해. AURORA/SNOW 등이 내부에서 sSTARS를 호출하는 경로에 새 능선을 섞지 않아 PR #17 아트를 보존해.

[Unreal Sky Atmosphere 문서](https://dev.epicgames.com/documentation/en-us/unreal-engine/sky-atmosphere-component-in-unreal-engine)의 대기 원근감 개념을 참고했지만, Unreal이나 물리적 대기 산란 모델을 포팅하지 않았어. 1차는 방향 기반 스타일 연출이었어. 2차에서는 별도 유한 거리 모델을 추가했지만 여전히 완전한 지형/대기 산란 시뮬레이션은 아니야.

이 보강은 순수 최적화가 아니야. 아래쪽 배경에 추가 산술이 있고 달 표면 계산도 하나 더 있어. 프레임 시간/실기기 검증 없이 공짜 효과라고 주장하지 않아.

## 과학적 조사 이후의 2차 구현: 깊이 단서가 서로 맞도록

사용자가 실제 Sphere의 몰입 원리를 별도로 조사하도록 요청한 뒤, 그 원리를 이 프로젝트에도 구현하라고 승인했어. 따라서 1차의 ‘관객 기준 무한 원경’만으로 마무리하지 않았어.

### 원리와 적용의 구분

- 넓은 물리적 시야는 디스플레이와 관람 거리의 특성이야. 브라우저 카메라의 FOV를 무작정 넓히면 작은 화면에 더 많은 풍경을 압축할 뿐, 실제 주변 시야를 채우지 못해. 자동 줌·강제 카메라 흔들기·풀스크린 강요는 넣지 않아.
- [Keshavarz 등, 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5423592/)의 돔/다중 모니터 실험은 넓은 시야와 자기운동감의 관계를 지지하지만 곡면 자체의 우월성이나 이 제품의 몰입도를 증명하지 않아.
- [Landy 등, 1995](https://www.cns.nyu.edu/~msl/papers/landyetal95.pdf)의 깊이 단서 통합 관점에 따라 가림, 거리에 따른 대비, 상대적인 움직임이 같은 깊이 순서를 말하도록 설계했어.
- [Alais & Burr, 2004](https://pubmed.ncbi.nlm.nih.gov/14761661/)는 시청각 단서의 신뢰도 기반 통합 연구야. 이 연구에서 ‘모든 음악에 맞춰 화면을 번쩍이면 몰입한다’는 결론을 끌어내지 않아. 기존 공간 음향은 그대로 두고, 느린 음악 에너지 변화만 국소 빛에 연결해.
- [Slater, 2022](https://www.frontiersin.org/journals/virtual-reality/articles/10.3389/frvir.2022.914392/full)의 장소감/개연성 구분은 설계 관점이지 이 PR의 사람 대상 실험 결과가 아니야.

### 유한 거리의 2.5D 배경

새 `dome-depth.js`는 관객 광선과 수직 원통의 교차점을 해석적으로 계산해. 관객 위치 o, 단위 시선 d, 원통 반경 r에 대해 a=dx²+dz², b=ox·dx+oz·dz, c=ox²+oz²−r²를 계산하고 양의 교차 거리 t=(−b+√(b²−ac))/a를 사용해. 그 교차점의 방위/고도에서 풍경을 평가해.

- 밤의 능선: 1000/400/160 world units. 먼 산은 작게, 가까운 산은 크게 이동해. 달과 별은 여전히 사실상 무한 거리이므로 좌석 이동으로 옆으로 끌려가지 않아.
- 달 앞 구름: 240 units. 구름이 달을 가리는 기존 구조에 상대 시차를 더해, 모두 같은 평면에 붙어 움직이는 느낌을 줄여.
- 저사양 FOREST의 나무: 500/220/100 units, 수관 130 units. 기존 나무 색·질감·배치 알고리즘을 유지하되 거리별 광선을 따로 사용해. 가까운 줄기가 먼 줄기를 가리는 순서는 유지해.
- 공연장 투영 모드는 원점이 기존 sweet spot에 고정돼. 실제 LED 스크린처럼 공유 표면을 보는 모드와 방문자별 시차를 제공하는 가상 공간 모드를 혼동하지 않아.
- 모든 레이어는 객석 밖에 있어. 실제 관객 위치의 수평 반경보다 충분히 크지만, 개발자 콘솔로 무한히 멀리 카메라를 보내는 경우까지 지원하는 월드가 아니야. 천정/바닥 수직 광선은 원통과 교차하지 않으므로 안정적인 원래 방향으로 돌아가.

이것은 완전한 3D 숲/지형이나 양안 VR이 아니라 **유한 깊이를 가진 2.5D 원경**이야. 지형 안으로 걸어 들어갈 수 없고, 새 geometry/텍스처/렌더타깃/렌더패스는 추가하지 않아. 단, 제곱근·삼각함수 등 픽셀 연산 비용이 증가하므로 ‘공짜’라고 표현하지 않아. 고품질 FOREST3D 등 기존 큐브맵 세계를 개별 관객 위치에서 다시 레이트레이싱하지도 않아.

### 음악과 빛: 짧은 박자보다 느린 에너지 변화

기존 level 입력을 1.8초 시정수의 지수 평활화로 처리한 `uPhrase`를 두 패스가 공유해. 이름은 연출용 envelope이고 악보의 구절/화성/마디를 실제 분석한 값은 아니야. 정지 상태에서는 0으로 부드럽게 내려가. 밤 계곡 안개와 숲의 햇빛 줄기에만 제한된 진폭으로 적용해. 지평선·달·나무 위치를 비트에 맞춰 흔들거나 화면 전체를 점멸시키지 않아. 기존 PCM, 샘플, 음악 시계, spatial audio, 통로 밝기는 변경하지 않아.

### 검증과 성공 기준

- CPU reference: 중심 시점 불변, 가까울수록 큰 시차, 움직이는 관객에서 고정 세계 지점의 좌표 불변, 수직 광선의 유한성.
- 제어기: 평활화의 프레임레이트 독립성, pause 시 감쇠, 모드/크로스페이드 전환 시 envelope 보존.
- 실제 제품 shader: MOON/FOREST/ARCH 및 다른 장면의 중앙/측면/상층 렌더, shader 오류와 모드 저장 확인.
- 동일 카메라 이동·동일 시간/입력으로 전후 영상 비교. 영상 샘플링 속도를 앱 FPS로 주장하지 않아. 실제 음악을 듣지 않은 합성 입력 시험은 청취 검증과 구분해.
- 사람의 몰입 체감과 멀미 여부는 아직 검증하지 않았어. 이 PR은 그 단서들을 일관되게 구현한 것과 렌더 안정성을 검증하는 것이지 ‘몰입도가 몇 퍼센트 올랐다’는 실험이 아니야.
