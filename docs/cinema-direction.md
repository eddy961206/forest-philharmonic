# 편하게 보기 — 자동 카메라 연출

기존 카메라는 14~20초마다 우세한 파트 중심으로 장면을 골랐다. 새 카메라는 공연장 전경, 관객석에서 보는 합주, 연주 중인 단원, 지휘자를 하나의 공연 중계처럼 섞는다.

- 처음에는 공간을 보여준다. 이후 7장면 단위로 전경 1회, 단원 4회, 관객석 시점 1회, 지휘자 1회를 배분한다. 지휘자가 없는 곡은 연주자 장면으로 대체한다.
- 중간 순서는 무작위로 섞되 단원 장면 세 개가 연속되지 않도록 제한한다. 무작위 조합 재시도 횟수에도 상한을 둔다.
- 실제 악보에서 현재 울리는 음, 1.5초 안의 진입, 최근 0.35초 안에 끝난 음 순으로 대상을 찾는다. 같은 활동 등급 안에서 파트·자리별 등장 횟수를 먼저 비교한다. 음 개수 대신 최대 음 세기와 트랙 음량을 사용해 반주 화음의 음 개수에 치우치지 않는다.
- 같은 단원을 다시 촬영하면 각도를 순환한다. 좌우 사선, 높이, 중간 거리와 파트가 함께 보이는 구도를 섞는다. 피아노는 건반·연주자가 보이는 전용 구도를 사용한다.
- 연주자 장면은 8~10초다. 3개 이하 파트 편성과 조용한 파트는 10~12초 머무른다. 전경·객석·지휘자는 10~12초다. 1.2초 안에 마디 첫 박이 있고 총 12초를 넘지 않으면 그 박에 맞춰 전환한다. 박자 자료가 없으면 기본 간격을 쓴다.
- 각 장면 안에서는 작은 이동을 천천히 이어간다. 4m보다 먼 이동이나 36도보다 큰 방향 전환은 컷으로 처리한다. 가까운 이동만 2.4~3.6초 동안 부드럽게 연결한다.
- 카메라의 출발점과 느린 이동 경로에서 주변 머리·피사체 가림·지면 높이를 검사한다. 위험한 이동은 축소하거나 정지한다. 피아노는 얼굴이 뚜껑에 가리지 않도록 높은 사선·건반 뒤쪽의 세 구도를 사용한다. 세로 화면에서는 근접 시점을 0.65m 높이고 주변 단원과의 최소 거리를 1.5m로 늘린다. 회전이 ±π 경계를 지날 때 한 바퀴 돌아가는 현상도 방지한다.

## 단원 뒤에서 객석을 보는 구도

연주자 장면 세 번 중 한 번은 무대에서 객석을 바라본다. 처음 순환할 후면 각도는 무작위로 고르고, 이후 어깨 뒤 사선 → 반대쪽 넓은 사선 → 합주 뒤 높은 구도를 순환한다. 현재 울리는 단원 선택, 7장면 편집 순서, 8~12초 간격과 박자 맞춤은 그대로 사용한다.

- 객석 방향은 세 공연장 모두 +Z다. 시선은 선택한 단원보다 객석 쪽으로 보내 단원과 악기를 아래 전경에, 객석을 배경에 둔다.
- 피아노는 연주자의 실제 방향(+X)에 맞춰 건반 뒤 왼쪽에서 촬영한다. 독주에서도 세 가지 후면 구도를 순환한다.
- 후면 장면은 컷으로 전환한다. 앞에서 뒤로 이동하면서 단원이나 악기를 가로지르는 경로를 만들지 않는다.
- 편집 시점에 실제 고정 악기 메시의 월드 경계 상자를 계산한다. 카메라와 느린 이동 경로가 그 안에 들어가지 않게 검사한다. 머리와 지형도 함께 검사한다.
- 무대 뒤 벽과 곡면 벽 안쪽에 카메라를 두고, 높이는 야외 차양보다 낮은 6.8m 이하로 제한한다. 세로 화면도 같은 검사를 거친다. 안전한 후면 위치를 찾지 못하면 기존 전경 장면으로 바꾼다.

후면 구도 전용 검사에서는 독주 피아노의 세 후면 각도 순환, 객석을 향한 시선, 모든 파트의 무대 경계 및 고정 악기 회피를 확인한다. 실제 메시 경계 상자는 보수적인 카메라 충돌 검사이며, 모든 음표 순간의 동작이나 모든 악기 가림을 완전히 제거한다는 뜻은 아니다.

선택은 장면 전환 때 계산한다. 매 프레임 전체 악보를 다시 읽지 않으며, 정렬한 음표의 종료 구간을 이진 탐색한다. 새로운 곡은 기존 악보 형식과 실제 자리 배정을 그대로 사용한다.

## 홀·스피어의 하강 공간 소개

홀과 스피어에서는 후면 장면 두 번 중 한 번에 공간 소개 구도를 섞는다. 후면 장면의 전체 빈도와 연주 대상 선택, 8~12초 호흡은 바꾸지 않는다. 야외는 기존 차양 아래 후면 구도를 사용한다.

- 카메라는 6.5m 높이에서 시작해 3.5m까지 내려온다. 세로 화면의 끝 높이는 3.8m다. 시작과 끝에서는 속도를 줄이는 곡선을 사용한다.
- 내려오는 동안 시선은 객석에서 발코니·천장 쪽으로 천천히 올라간다. 홀의 수직 시야각은 96도, 스피어는 100도다. 단원이 있는 무대에서 시작해 공연장의 높이를 드러낸다.
- 출발점과 도착점뿐 아니라 이동 구간 전체를 검사한다. 고정 악기 경계 상자와 수직 이동 구간의 교차, 머리에서 경로까지의 최단거리, 33개 지형 표본과 시선 경로를 확인한다.
- 합주 뒤 중앙의 여덟 위치를 검토한다. 측면에서 단원을 프레임 밖으로 보내는 후보는 사용하지 않는다. 안전한 하강 경로가 없으면 이미 검사한 기존 후면 구도를 유지한다. 위험한 경로를 짧게 줄여 억지로 하강하지 않는다.

카메라 전용 검사 16개에는 야외 제외, 실내 구도의 하강·상향 시선, 기존 후면 구도와의 혼합, 이동 중간에만 놓인 악기 때문에 전체 하강을 거부하는 경우가 포함된다.

### 하강 구도 v1 검사 — 전경 유지 요구 미달

첫 하강 구도는 홀·스피어의 공간을 보여줬지만, 스피어 마지막에 단원이 화면 밖으로 빠졌다. 홀에서는 큰 머리 하나가 두드러졌다. 전환 간격과 충돌 검사를 통과했어도 **연주자 여러 명의 뒷모습을 끝까지 유지한다는 요구는 충족하지 못했다.** 이전 영상은 실패 사례로 보존한다.

v2는 카메라를 합주 뒤 중앙에 두고 상향 시선을 줄인다. 편집 시점의 실제 단원 월드 위치·크기와 현재 곡의 자리 배정을 사용한다. 이동 구간의 33개 위치마다 머리와 상체를 화면에 투영한다. 합주는 최소 세 명, 세 명 미만의 편성은 전원이 화면 아래쪽에 남아야 선택한다. 피사체와 최소 3m 거리를 두어 한 머리만 크게 잡히는 구도를 줄인다. 이 조건을 만족하는 안전 경로가 없으면 기존 후면 구도로 돌아간다.

하강 컷의 첫 프레임부터 검사한 넓은 화각을 바로 적용한다. 이전 장면의 좁은 렌즈를 서서히 넓히는 동안 단원이 잘리는 것을 막는다.

회귀 검사에서는 실제 Three Group 단원 배치를 사용하고, 홀·스피어의 이동 구간을 101개 위치로 나누어 머리와 상체가 최소 세 명 이상 화면에 남는지 확인한다.

### 하강 구도 v2 최종 확인

홀과 스피어에서 실제 자동 편집을 각각 50초 녹화했다. 작업자와 root가 시작·중간·끝 프레임을 직접 보고, 여러 단원의 뒷모습·상체·악기가 전경에 남으면서 객석과 천장·돔이 함께 보이는 것을 확인했다. 이전 v1의 공간 단독 끝 구도를 수정한 결과다.

## 후면 구도 확인 — 2026-10-25

카메라 전용 검사 11개가 통과했다. Chrome의 실제 자동 편집을 야외 120초, 홀 40초, 스피어 40초, 세로 화면 피아노 독주 40초 녹화했다. 총 24장면에서 연주 대상 자격·8~12초 간격·페이지 visibility·콘솔 오류 검사를 통과했다. 후면 5장면에 세 종류가 모두 포함됐다.

후면 장면의 시작과 끝을 시간순 프레임으로 확인했다. 확인한 프레임에서 머리·악기·지형 관통은 없었다. 피아노 세로 구도는 연주자와 건반 일부를 왼쪽 전경에 두고 객석을 배경에 담는다. 피아노 전체를 한 화면에 넣는 구도는 아니다. 모바일 검사는 Chrome 390×844 에뮬레이션이며 실제 iPhone/Safari 검사는 아니다.

후면 검사 제품 JS SHA-256: `45419db4520f32265f7b6e723c27ad5596a9d764f80960822d1aa6c8daa8878a`.

재현할 때는 아래 기존 명령 앞에 `CDP_PORT=9225`를 지정할 수 있다. 녹화 도구는 최대 180초 녹화를 위해 통신 제한을 240초로 두고, JSON에 후면 구도 이름(`view`)도 기록한다. 첫 180초 녹화의 도구 시간 초과와 조기 탭 종료로 중단된 홀 녹화는 최종 결과에서 제외하고 재녹화했다.

## 재현

```sh
npm run verify:motion -- --out work/cinema/verification
QA_OUT=work/cinema node tools/qa/record-cinema.mjs outdoor 75
QA_OUT=work/cinema node tools/qa/record-cinema.mjs hall 45
QA_OUT=work/cinema node tools/qa/record-cinema.mjs sphere 45
MOBILE=1 QA_OUT=work/cinema node tools/qa/record-cinema.mjs outdoor 45
```

전용 `cdp-direct` Chrome 9224와 로컬 서버 8096을 사용한다. 녹화 도구는 실제 자동 카메라를 켜고 화면·소리를 연속 녹화한다. 카메라를 검사 전용 고정 위치로 바꾸지 않는다. 실제 편집 시간, 각도, 단원, 곡의 음표로 독립 확인한 활성 여부, visibility와 콘솔 오류를 JSON에 남긴다. 녹화 중 다른 자동화 연결로 뷰포트를 변경하지 않는다.

검증 환경은 Mac mini M4, Chrome 156이다. 모바일은 Chrome 에뮬레이션이며 실제 iPhone/Safari 검사는 포함하지 않는다. 선택 시점의 실제 음표 검사는 모든 촬영 시간 동안 피사체가 계속 소리를 내거나 모든 물체의 가림이 제거된다는 보장은 아니다. 전곡 완주 영상 검사도 아니다.

결과와 실제 영상은 `docs/evidence/cinema/`에 보존한다.

최신 야외 전용곡·후면 카메라 결과는 [최신 통합 검증 기록](outdoor-exclusive-validation.md)을 참고한다. 아래는 2026-10-24 당시 결과다.
