# 전체 악단 동작 수정과 검증

## 범위

새로 추가한 곡에 한정하지 않고 두 공연장의 기존 곡·단원도 같은 기준으로 검사했어. 대상은 등록된 **82곡, 단원 51명과 지휘자, 동작 유형 30개**야. 연주, 휴식, 탐색, 일어나기, 인사, 입장, 퇴장을 포함해.

동작 구현과 영상·성능 검증은 주 에이전트가 진행했어. 사용자가 서브에이전트 활용을 요청한 뒤 GPT-6.1 Sol / medium에게 하네스 검토와 예외 처리 보강을 맡겼어. Vercel 배포는 사용자가 중단한 상태로 유지했어.

## 발견한 문제와 수정

| 문제 | 원인 | 변경 |
| --- | --- | --- |

| 타악기를 귀 높이에서 치거나 허공을 두드림 | 여러 악기가 팀파니 동작을 공유 | 악기별 타점·채·진행 방향 분리. 트라이앵글은 한 개의 금속 채, 탬버린은 한 손 지지와 반대 손 타격 |
| 탐색·정지 후 손이 튐 | 이전 음의 활·타격 상태를 재사용 | 곡 변경과 시간 이동 때 상태 초기화. 활과 타점의 횡방향 이동 제한 |
| 입퇴장 때 뒤쪽 피아노로 팔을 뻗음 | 이동 중에도 무대 위 악기 목표점을 추적 | 이동 자세와 연주 자세 분리. 착석 뒤 부드럽게 연주 자세로 복귀 |
| 일부 단원이 가구를 통과함 | 큰 악기가 계단을 막고, 단차 사이 이동 경로가 끊김 | 큰 고정 악기 4개를 평평한 측면으로 이동. 렌더링·길찾기가 같은 정의를 쓰는 연결 계단 9개 추가 |
| 너구리 눈 주변이 검은 띠처럼 보임 | 가로로 연결된 검정 무늬 | 머리 곡면에 맞는 두 개의 부드러운 갈색 무늬와 둥근 귀로 수정 |

기존 팔 인스턴싱은 유지했어. 음원과 음질 설정은 이번 동작 수정에서 바꾸지 않았어.

마지막 영상 검토에서는 벨의 채가 주둥이를 관통하는 문제도 찾았어. 기존 팔 접촉 검사로는 발견하지 못했어. 실제 머리·주둥이·코 모델에서 충돌 타원체를 가져오고 채 선분과의 거리를 검사하도록 추가했어. 이전 10초 벨 구간의 1,200개 채 표본 중 531개가 관통했어. 타점을 낮추고 채의 방향과 반동을 수정했어. 다른 고정 타악기도 몸에 맞는 손잡이 방향으로 수정한 뒤 전체 검사를 다시 실행했어.

## 자동 검사

`npm run verify:motion`이 단위 검사와 동작 검사를 한 번에 실행해. 실패 원인과 재현 명령은 JSON으로 반환하고, 51개 실제 단원별 녹화 계획도 생성해. [AI 작업 절차](motion-harness.md)와 루트 `AGENTS.md`에 사용법을 남겼어.

`npm run check:motion`은 실제 `SETLISTS`를 읽어. 별도로 82곡 목록을 복사해 놓지 않았어. 곡이나 공연 목록이 늘어나면 검사 대상도 늘어나.

각 곡의 시작, 25/50/75/95% 지점, 각 파트와 특정 자리의 첫 진입 및 음이 가장 밀집한 구간에서 2초를 60 Hz로 계산해. 이어서 0.5초의 정지 전환도 검사해. 전체 단원의 인사·퇴장·입장은 별도로 끝까지 진행해.

## 영상 검사 방식

실행 중인 앱의 `canvas.captureStream(30)`과 실제 Web Audio 출력을 함께 녹화했어. 정지 화면을 이어 붙여 연주 영상으로 만들지 않았어. 영상과 함께 매 렌더 프레임의 손·팔꿈치 좌표, 굽힘 각도, 목표점 오차, 타격 상태, 활 표시, 채와 손 사이 거리도 저장했어.

검토에는 실제 녹화에서 시간순으로 추출한 연속 프레임과 그 사이의 프레임별 관절 궤적을 사용했어. 공유하는 MP4에는 정상 속도의 연속 영상이 들어 있어. 각 악기 유형, 지휘, 인사, 전체 입퇴장을 따로 확인해.

검사 도구 자체도 보강했어. 존재하지 않는 파트를 고르면 실패하고, 녹화 구간에서 해당 단원이 실제로 연주한 프레임이 없으면 실패해. 처음 플루트를 쉬는 구간에서 찍은 경우와 오보에가 없는 곡을 지정한 경우를 이 기준으로 수정·재녹화했어. 피아노 덮개나 보면대가 손을 가리는 카메라는 바꿔서 다시 녹화했어.

[사례별 관찰 기록](evidence/character-motion/visual-review.md), [촬영 조건과 해시](evidence/character-motion/recording-summary.json), [프레임별 관절 원자료](evidence/character-motion/frame-telemetry.json.gz), [구간 이동용 로컬 페이지](evidence/character-motion/review.html)를 함께 저장했어. HTML과 MP4를 같은 폴더에 두고 열면 악기별로 바로 이동할 수 있어.

수정본 39개 녹화에서 브라우저 오류는 0이었어. 촬영 대상 단원의 손 목표점 최대 오차는 0.002687였어. 퇴장 마지막에는 무대 위 단원 0명, 입장 마지막에는 착석 39명·서 있는 합창 12명·이동 중 0명이었어.

## 성능 재측정

Apple M4 / RAM 32 GiB / macOS 26.5.1 / Chrome 156.0.8078.47에서 측정했어. 이전 QA 앱 탭을 닫고 전용 Chrome 9224의 보이는 연주 화면을 사용했어. 녹화·영상 인코딩·단위 검사는 측정과 동시에 실행하지 않았어.

- 데스크톱: 1200×800, DPR 1, 높은 화질, renderScale 1.
- 모바일 에뮬레이션: 390×844, 기기 DPR 2, 실제 렌더 pixelRatio 1.25, Lite 설정, renderScale 1.
- 홀은 위풍당당 280초, 스피어는 발퀴레 277초부터 재생했어. 5초 준비 후 각 20초를 측정했어.
- 주 카메라를 무대에 고정했어. 조명·음표·전체 오디오·전광판의 자동 카메라는 계속 동작했어. 전광판의 컷과 시스템 부하 차이 때문에 매 실행의 그리기 호출 수는 같지 않아.

## 검증한 소스

최종 수치 검사와 추가 녹화·성능 측정에 사용한 `public/js` 61개 파일의 SHA-256은 `5e6510e15b1e8b8843b42335462df290fa6de0ba875a3bae0b61d6047ae26c8d`야. 고정 타악기 7개, 모바일 벨, 인사·입퇴장 영상은 마지막 충돌 수정 후 다시 녹화했어. 나머지 영상은 해당 연주 방식 수정 후의 앞선 녹화이며 파일별 해시를 `recording-summary.json`에 남겼어. 전체 영상을 최종 소스에서 동시에 촬영했다고 주장하지 않아.

이전 영상의 `40d154…`와 `0977c2…` 간 차이는 `orchestra.js` 끝의 빈 줄이었고 `source-cleanup.diff`에 남겼어. 최종 해시는 얼굴 충돌 메타데이터와 타악기 자세 수정을 추가로 포함해. 통합 검증의 `inputs.sha256`은 악보·검사 코드까지 포함한 별도 해시야.

각 JSON의 `baseCommit`은 수정 전 작업 기준 커밋을 뜻해. 수정 파일을 포함한 실제 검증 대상은 `sourceSHA256`으로 식별해. 비교 영상 8개는 이전 커밋 `79b5c025e469c0654fde8c7ccdbc49aed2cea6a1`의 전체 브라우저 JS를 사용했어.

## 곡·장소·악단을 추가할 때

1. **곡**: 실제 악보 JSON과 공연 목록을 등록해. `check:motion`이 새 곡과 파트 진입 구간을 자동으로 읽어. 새로운 연주법이 있으면 관련 rig와 `MOTION_CASES`에도 대표 영상 사례를 추가해.
2. **단원**: `SECTIONS`와 `CAST`의 자리·체형을 같이 등록해. 전체 단원은 관절 검사와 입퇴장 경로 검사에 자동으로 포함돼. 악기 타입에 대응하는 rig가 없으면 명확한 오류를 내.
3. **악기**: 악기 모델의 실제 접촉점과 그립을 정의해. 악기를 몸에 붙일지 무대에 고정할지 명시하고, 배율과 좌표 변환을 적용한 후 `setArm`에 몸 좌표 목표점을 전달해. 접촉 실패를 팔 늘리기로 가리지 않아.
4. **장소**: 현재 두 공연장은 악단과 무대 모델을 공유해. 같은 무대를 쓰는 새 공연장도 무대 계약을 명시해야 하며 미등록 장소는 실패해. 곡 목록은 자동 수집해. 무대 구조 자체를 새로 만들면 렌더링과 길찾기가 같은 바닥 정의를 사용하게 하고, 그 무대의 입퇴장 사례도 추가해야 해. 현재 수치 검사만으로 아직 만들지 않은 무대를 검증했다고 볼 수는 없어.
5. **완료 기준**: `npm run verify:motion` 결과를 남겨. 기존 방식의 악보만 추가하면 매 곡 스크린샷이나 영상을 요구하지 않아. 외형·자세·악기·무대 구조를 바꾸면 영향을 받는 사례의 연속 영상을 확인하고, 렌더링 성능에 영향을 주는 변경은 녹화 없는 성능 검사도 남겨.

## 하네스 독립 검토와 재현 확인

GPT-6.1 Sol / medium이 하네스를 읽고 검사 누락과 실패 처리 방식을 검토했어. 특정 자리만 늦게 진입하는 악절, 지휘자 완료 상태, 비정상 채 좌표, 불완전한 결과 파일의 성공 처리 문제를 찾아 보강했어. 추가 검토에서 null 자료와 상속된 속성 이름으로 인한 예외 처리도 수정했어. 에이전트의 집중 회귀 검사는 7/7, 주 에이전트의 최종 전체 회귀 검사는 253/253 통과했어.
