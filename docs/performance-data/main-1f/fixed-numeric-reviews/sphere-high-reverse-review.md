# Sphere high 첫 A/B와 역순 B/A 파일 검토

**결론: 완료시간은 혼합된 결과이고 12장면 중 6장면에서 반복 간 방향이 바뀌었어. Sphere 전체 성능 개선을 입증하는 결과로 쓰면 안 돼.**

같은 버전의 draw call·삼각형 개별 표본 배열은 두 반복에서 일치해. 중계의 draw call 감소와 3D world proxy의 삼각형 감소는 재현됐지만 완료시간과 항상 같은 방향은 아니야.

## 범위와 원본 검증

- 상태: FILE_REVIEW_PASS. 전체 파일/조건 확인 683건 중 실패 0건.
- baseline: `1f8e5f16f1eee03140e13ba1ee66832841559604`; candidate: `dea7997c6278f10ff467815ab96b370362549b0c`.
- 첫 순서는 baseline-a → candidate-a, 역순은 candidate-b → baseline-b야. 각 장면 warmup 4개 뒤 완료 표본 8개, 12장면×4실행=384개야.
- Headless Chrome 153.0.8010.0, Playwright 1.64.1, Linux x64, SwiftShader, viewport 640×360, DPR1, high/renderScale1/full 경로야.
- Beethoven, 관객 12,863명, 좌석 13,851개(일반 관객 배치 후보 13,845개·무대 특별 좌석 6개), 고정 seed와 카메라/FOV가 일치해.
- 소스 12경로의 전후 SHA·manifest, 계획/실행 로그 SHA·동결 수집기, 60개 해당 원본/로그/PNG의 canonical·전송 manifest·staging SHA를 대조했어.
- 48개 장면의 돔 base와 필요한 overlay warmup draw·프로그램 ready/link가 확인됐어. 384개 측정 표본은 high/scale1/visible/awake, GL 오류0/context loss false였어.

## 해석 한계

- 동일 호스트/브라우저/SwiftShader 설정이지만 첫 쌍 종료(11:25:31 UTC)와 역순 시작(13:58:16 UTC) 사이 약 2시간 33분이 있어. 실제 CPU/GPU 클록·열·호스트 경합을 측정하지 않았으므로 방향 차이 원인을 실행 순서만으로 확정하지 않아.
- 두 반복은 각 버전·장면에 16개 표본일 뿐이야. 그 16개를 독립 반복 16회로 간주하거나 신뢰구간·일반 기기 FPS로 확대하지 않아.
- 카메라 pose/FOV·음악 시작 시각·고정 seed·fixture 해시가 같아. 이 수집기는 실제 카메라 행렬을 표본마다 별도 저장하지 않으므로 per-frame pose 직접 검증은 아님.
- rotate는 ARCH 셰이더에서 고정식으로 움직이는 경로야. 3D world의 새 큐브 면 검사와 실제 마우스/터치 입력은 이 suite가 입증하지 않아.
- crossfade/reveal은 60초 전환을 중간 시각으로 진행한 뒤 4 warmup+8개 step을 보는 구간이야. 4초 전환 전체·시작/종료 또는 모든 프레임의 신선도를 검사하지 않아.
- 품질 high, renderScale1, DPR1, viewport640×360 full 경로만 대조했어. 모바일/실제 스마트폰/Safari/Edge 결과와 섞지 않아.
- 초기 UI·돔 visible 및 warmup 프로그램 게이트는 확인했지만, 음표 스케줄러는 꺼지고 합성 음악 시계를 사용했어.
- GPU timer extension 노출은 측정값이 아니야. GPU frame time·VRAM·배터리·발열·장시간 안정성을 이 결과로 입증하지 않아.
- 소스 해시의 직접 대조는 HTTP로 수집한 12개 파일에 한정돼. UUID 난수 분리와 main fixture 주입 실행이라는 계측 조건이 있어.
- PNG는 SHA만 읽었어. 이전 첫 A/B 육안 보고서는 별도 자료이고 이번 역순 PNG의 화질 검토를 대체하지 않아.

## 재계산 방법

기준 파일은 fixed/render의 `{baseline-a,candidate-a,candidate-b,baseline-b}-full-sphere-high-desktop-sync.json`이야. 각 `scenarios[name].samples`에서 completeMs 산술평균과 정렬 후 ceil(.95×8)−1 위치를 구하고, CDP before/snapshot 배열을 이름으로 대응해 차이×1000을 구했어. 호출·삼각형도 각 samples에서 다시 계산한 뒤 저장된 summary와 대조했어.

검토에 사용한 표준 라이브러리 스크립트와 SHA는 JSON의 provenance.reviewScript에 기록돼. 원본 JSON·로그·전송 manifest가 있어 같은 계산을 독립적으로 재현할 수 있어.
