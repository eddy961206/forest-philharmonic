## 한계·검증하지 않은 범위

- 각 제품·각 실행·장면당 연속 표본은 8개이고 예열은 4회다. a와 b는 순서를 뒤집은 별도 실행으로 나란히 제시하며 합쳐 n=16인 독립 표본이나 신뢰구간을 만들지 않는다.
- p95/p99는 nearest-rank이며 n=8에서는 둘 다 최대값이다. 방향 반복은 통계적 유의성이나 일반 하드웨어 재현성의 증명이 아니다.
- SwiftShader 소프트웨어 렌더러의 640×360 desktop viewport 결과다. 물리 GPU·실제 PC/스마트폰 FPS를 주장하지 않으며 completeMs 역수를 FPS로 변환하지 않는다.
- completeMs는 실제 frame 호출과 동기 readPixels 대기를 포함한다. GPU timer extension 존재만 기록됐고 이 수집에서 GPU query 시간·VRAM을 측정하지 않았다.
- ΔThreadTime은 페이지 renderer 메인 스레드의 계측 포함 CPU 실행시간이라는 기존 버전 소스 검토 범위로 읽는다. ΔTaskDuration/ScriptDuration은 기본 timeTicks 경과시간으로 동기 대기·계측을 포함하며 CPU 사용률이 아니다. SwiftShader 작업 스레드/별도 GPU 프로세스의 총 CPU를 나타내지 않는다.
- performance.memory 기반 표본 heap과 CDP JSHeapUsedSize를 별도 표기한다. coarse 값·GC·수집 시점·계측 경계의 차이가 있으며 합산하거나 총 메모리/VRAM 감소로 해석하지 않는다.
- served source before/after는 raw에 기록된 12개 경로만 검증했다. source manifest 49개가 Git에 맞는 것은 모든 49개 HTTP 응답을 실행 중 기록했다는 뜻이 아니다.
- 관객 수·seed·fixture hash·장면 설정은 같지만 raw에 관객 좌석별 점유 hash나 프레임마다 전체 카메라 행렬·모든 auxiliary camera·caption wall-age/font readiness snapshot은 없다. 환경 메타데이터 일치는 독점 CPU 자원이나 동일 열 상태 증명이 아니다.
- PNG는 존재·바이트 수·SHA만 확인했다. hash가 다르면 픽셀 차이 원인이나 화질 저하를 이번 리뷰에서 판정하지 않는다. 캡처 시점 PNG hash가 raw에 없어 현 파일을 식별하는 사후 해시라는 한계도 남는다.
- 이 fixture는 UI를 숨기고 실제 note scheduler를 끈 합성 공연 시계를 사용한다. 음질·glitch·실제 UI 이동/좌석/seek·멀티플레이·광장·장시간 감상·열/배터리 안정성 검사가 아니다.
- Hall high만 검토했다. medium/low/mobile·다른 공연장·전체 계획 완료율은 이 리뷰의 결론에 포함하지 않는다. 원본 실패/미완료를 통과로 대체하거나 유리한 행만 선택하지 않았다.
- a 첫 리뷰에서 실행된 2.294초 이미지 작업의 보수적인 창은 12:51:33~13:01:38 UTC이며 이 b 실행(13:40:15 이후)과 겹치지 않는다. 이를 b의 완전한 자원 격리 증거로 삼거나 다른 변동 원인을 확정하지 않는다. 이번 검토에서는 이미지 decoding/SSIM/브라우저/GPU를 실행하지 않았다.
